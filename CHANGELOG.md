### 2026-09-17b (Australia/Sydney) — provenance at ingestion: three weaker definitions of "public" were implemented, demonstrated exploitable, and rejected
**Raouf:**
- **Scope:** `scripts/provenance.py` (new), `scripts/ingest.py` (frontmatter + accession + `--public-url`), `tests/test_ingest_provenance.py` (new, 37 contracts), Boundary spec §8.
- **The open item that blocked the FP gate is implemented.** `ingest.py` recorded `title`, `hash`, `figures`, `extraction_status` and `ingested_at` — nothing about origin — so a document's class came from the directory it landed in. Everything under `wiki/sources/` was PRIVATE, including this repository's own README, and Boundary then correctly refused to let the original public file be committed. A source page now carries `origin_class` and `origin_provenance`, decided when the document is acceded.
- **Three classes, because "public" is not one thing.** `PRIVATE -> PUBLIC_DECLARED -> PUBLIC_VERIFIED`. Only `PUBLIC_VERIFIED` is acceded to D3, so only it can exempt a span; `PUBLIC_DECLARED` is recorded for audit and never honoured, because an unverified claim that grants an exemption *is* the laundering primitive.
- **Three weaker predicates were written, shown to be exploitable, and rejected.** (1) `git cat-file -e` proves an object EXISTS — `git hash-object -w` satisfies it with no commit, ref or intent; measured on a real repository, the dangling blob reports EXISTS while `git log --find-object` correctly finds nothing. Anyone able to write a file could have manufactured public provenance. (2) `git log --all` means every ref under `refs/`, including `refs/stash`, `refs/original/*` and scratch branches; measured, a stashed file and a temp-branch file were both found, so `git stash` would have laundered a private document. (3) The index is not a sink: `git add` is local, unshared and reversible, so staging a document to have it acceded and then unstaging it would leave the text exempt forever.
- **`PUBLIC_VERIFIED` = reachable from an ALLOWLISTED ref in the repository this gate protects.** Default allowlist is the canonical branch as git reports it (`origin/HEAD`, else `main`/`master`); a repository with neither verifies nothing. `ZURVAN_PROTECTED_REFS` declares release refs. A **foreign repository** classes DECLARED: `git init && git add && git commit` in a scratch directory is not a publication event, and treating it as one would mean anyone who can run git can cross the boundary. One existing test was **inverted deliberately** — a side-branch commit no longer verifies until it is merged.
- **An accession is historical evidence** and survives a later reset, rebase or branch deletion: the disclosure already happened, re-validating would make a routine rebase silently re-block clean content, and revocation belongs in the declassification ledger rather than in `git rebase`. Stated cost: bytes acceded from a rewritten commit stay exempt until revoked — which is why each accession records the blob OID and a repository identity (its root-commit OID; a filesystem path would name a private project inside a stored page).
- **FP gate status — unchanged, deliberately.** Mechanism **IMPLEMENTED and experimentally validated**: an ingestion round-trip blocks without provenance (reproducing the 2026-09-16 class), clears with it, and private material still blocks. Legacy corpus **INVALID for the v2 criterion** — none of the ~4,400 existing pages carries a class, and Global Constraint 7 forbids upgrading them retroactively. The prior **11/200 remains historically valid** for the provenance-blind setup it measured. The v2 FP gate is **NOT YET MEASURED**: a qualifying post-provenance corpus does not exist yet.
- **Verification:** provenance contracts **37/37**; `boundary_redteam` **27/27**; `public_repo_guard` passed; `git diff --check` clean; full `pytest` recorded below. Committed locally; **not pushed**.
- **Follow-ups:** (1) Build the post-provenance FP evaluation corpus the v2 criterion requires — not by re-running the legacy one. (2) Commit-gate batching stays blocked until that measurement is valid. (3) `PUBLIC_DECLARED` has no promotion path yet: an audit that verifies a declared URL cannot record that finding.

### 2026-09-17 (Australia/Sydney) — the search index had two ways to die and no way to say so; both are closed, and one of them was mine

**Raouf:**

- **Scope:** `scripts/rebuild_search_index.py` (rewritten around a temp build + atomic swap), `scripts/index_health.py` (new), `scripts/agent_workflow.py`, `scripts/cli.py`, `scripts/check.sh`, `scripts/eval_search.py`, `scripts/hybrid_search.py`, `scripts/e2e_all_phases_until_17.sh`, `.claude/settings.json`, `.gitignore`, `tests/test_index_integrity.py` (new, 31 contracts), `tests/conftest.py`, `tests/test_agent_workflow.py`.

- **What was found.** The canonical index was unusable in two different ways at once. `data/search.sqlite` held **2,000 of 184,231 chunks** from **59 of 4,418 sources** — a SessionStart hook had started a rebuild at 13:23:49 and the session exited at 13:24:32, and SIGKILL left exactly one `COMMIT_EVERY` batch behind. `data/search.sqlite.prev` held the full 184,231 chunks and **every vector was `mock`/`deterministic_hash`**: a rebuild had run where `ZURVAN_EMBED_PROVIDER` was unset, in 38 seconds, replacing every real vector with a SHA-256 hash. Both files passed every check the project had. Counts agreed in both.

- **Root cause is one sentence in two places.** A rebuild wrote to the canonical path while it worked (`_PriorIndex` moved the live index to `.prev` first), so any interruption published a partial index; and `get_embedding` returns deterministic hashes as a successful result when the provider is unset **or when SentenceTransformers fails to load**, so any unpinned caller silently published hashes. `check.sh` gate 5 rebuilds the production index and pinned nothing — it is the likeliest source of the poisoning, run from a plain shell.

- **Atomic rebuild invariant.** The replacement is built at `data/search.sqlite.building-<pid>`, validated as a temporary file, and moved into place with one `os.replace()`. The previous index stays readable (read-only, in place) for embedding reuse throughout. Exception, SIGINT, SIGTERM, SIGKILL or a failed validation all leave the canonical path holding the old index; `.prev` no longer exists and carries no correctness weight. Leftovers from a killed run are swept by the next rebuild, and a build file owned by a LIVE process makes the next rebuild refuse to start.

- **Exact-provider invariant.** A rebuild aborts when the provider it received differs from the provider requested (the silent-fallback case), and a rebuild of the CANONICAL index aborts unless the space is exactly `sentence_transformers` / `all-MiniLM-L6-v2` / `384`. Pinning the environment does not close the fallback: an undownloadable model would have poisoned a "pinned" rebuild. `zurvan index search` now carries the production space itself rather than inheriting the shell it was typed into.

- **Health is no longer a row count.** `scripts/index_health.py` judges integrity, chunk/FTS/embedding agreement, source coverage, a SINGLE embedding space, that space being the expected one, and every vector's byte width. `zurvan index health [--deep]` exposes it, `check.sh` gate 5 enforces it, and the session-start card reports it — because both broken indexes reported "fresh" and answered queries exactly like a complete one. Asked with no stated expectation, an index of mock vectors is now UNHEALTHY rather than "healthy".

- **Test isolation is an invariant, not a guard — and this was my failure.** Mutation-testing the new guards, I removed both, and this file's own "a canonical rebuild is refused" test then rebuilt the production index and deleted it on the way out. The 2,000-chunk partial was already condemned and nothing of value was lost, but a guard whose own test can destroy the thing it guards has one point of failure. Canonical-path tests now run against a disposable root (`PROJECT_ROOT` monkeypatched into `tmp_path`); no rebuild of any canonical path can start while `PYTEST_CURRENT_TEST` is set; `conftest.py` fails the session if `data/search.sqlite` changes at all; and a meta-test rejects any test that starts a rebuild without naming a disposable target or redirecting the root.

- **Read paths were creating the index.** `sqlite3.connect` creates the file it cannot find, so `agent_prime` left a 0-byte database at the canonical path — turning "missing" into "unreadable" for everything downstream. `agent_prime`, `_index_staleness`, `eval_search` and `hybrid_search` now open `mode=ro`, pinned by a behavioural test.

- **Two hazards found by accident, both real.** A backtick inside a shell audit command executed `zurvan index search` and ran a second production rebuild for ten minutes beside the first; atomicity meant neither corrupted anything, which is the invariant working, but nothing refused the second one — the rebuild now does. And renaming the build artefact from `.prev` to `.building-<pid>` escaped `.gitignore`'s `data/*.sqlite`, leaving a 737 MB index of private knowledge one `git add -A` from being staged; the rules now match the shape rather than the spelling, with a test over every artefact name.

Corpus accounting: 4,365 wiki pages − 24 under `wiki/traces/` + 81 docs pages − 4 under `docs/evaluation/retrieval/` + 3 root files = **4,421 indexable files**. Coverage is 4,421 of 4,421 — nothing missing. Against the previous index's 184,231 chunks / 4,418 sources the difference is **+10 chunks / +3 sources**, fully attributable to three pages written after that index was built (6 + 2 + 2 chunks); **zero sources were removed**, so nothing was dropped. The poisoned index is kept for diagnosis at `data/quarantine/2026-09-16-mock-poisoned-search.sqlite` and is reported UNHEALTHY by name.

Validation now compares **both** the row count and `sum(origins.n_fingerprints)` against the committed total.
