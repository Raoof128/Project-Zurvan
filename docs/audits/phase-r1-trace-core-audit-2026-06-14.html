Threat Model

Phase R1 accepts local CLI input and local trace JSON. Trace contents may be attacker-influenced if an agent or user writes malformed trace files. Important assets are raw sources, existing wiki content, trace integrity, local filesystem boundaries, and reviewer trust in replay output.

  • Trace IDs must not allow path traversal.
  • Trace files must stay under data/traces/.
  • Markdown mirrors must stay under wiki/traces/.
  • Replay must not execute tools, read raw sources, or call networks.
  • Replay must refuse traces with invalid schema or payload hashes.

E2E Evidence

Happy-path E2E created a temporary trace project root, wrote JSON and Markdown through TraceStore, then ran trace list, trace inspect, trace validate, and trace replay.

Negative-path E2E confirmed invalid payload hashes block validation and replay, traversal-style trace IDs are rejected, missing traces return nonzero, and writer path safety rejects unsafe IDs.

Security Review

No reportable finding.

  • TRACE_ID_RE and EVENT_ID_RE reject path-like and malformed IDs.
  • TraceStore._paths_for() validates trace IDs before building paths.
  • TraceStore._ensure_under() confirms resolved paths remain under trace directories.
  • validate_trace_file() checks required fields, IDs, event types, duplicate events, payload types, and payload hashes.
  • replay_trace_file() validates the trace before rendering Markdown.

Residual Risks

  • Phase R1 does not yet integrate trace capture into retrieval, graph, or MCP tools. That belongs to later R2/R3 phases.
  • The trace schema validates structure and payload integrity, not semantic truth.
  • --project-root is an internal CLI test/audit override. Normal user routing should prefer --project.
