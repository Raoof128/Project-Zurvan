## 0. Shared constraints

- Every write goes through the CLI or MCP operation boundary and `write_file_safely`; nothing writes the live store
  in a test (`ZURVAN_ROOT` temp roots).
- No retrieval ranking or indexing change, so no `eval_search` delta; where a change touches a derived view, a test
  shows the live index bytes are unchanged until a page opts in.
- Authored Markdown is never rewritten. Decisions stay `authority=markdown`.
- Every new refusal has a closed code; every new command is either read-only (no operation) or one operation.
- The order of work: IOU-Z2-3, then -2, then -1, then -4 (smallest blast radius first).

## 1. IOU-Z2-3: retraction propagation into what is built from claims

**Today.** The claim view, search, context, graph and digest already drop a non-current claim (§7.5a, IOU-Z2-6).
What is *built from* claims and kept: syntheses (`search/context --save`, `scripts/context_export.py:112-146`),
evidence packs (`scripts/evidence_pack.py:34,48`) and reports (`scripts/report_compose.py:125`). Syntheses record
provenance only as a comma-joined `sources:` path list (`context_export.py:136`), and the synthesis writer uses a
raw `open()` (`:143`), outside the write barrier. Concept, entity and summary pages are built from the extraction,
not from claims (`scripts/wiki_merge.py:150-175`, `extract.py:209-213`), so they are out of scope. Live counts:
0 syntheses, 0 non-claim wiki pages citing a claim id.

**Design: propagate by report, never by rewrite.** A synthesis, pack or report is a point-in-time snapshot of what
was retrieved; rewriting it would falsify that record. So:
1. New syntheses record `claims: <id>, <id>` in frontmatter (flat scalar; the parsers are flat,
   `graph_build.py:28-42`), the claim ids of every claim page among their sources. The synthesis write moves to
   `write_file_safely` (fixes the barrier bypass).
2. `zurvan claim impact <id>` (read-only) lists every derived artifact citing the claim, matched by id (`claims:`)
   or by the claim page's path (older syntheses, packs, reports), with the artifact kind and path.
3. `zurvan claim stale-derived` (read-only) lists every derived artifact citing a non-current claim, with the claim's
   status. `claim doctor` prints its count (informational, never a failure).
4. `claim supersede`, `retract` and `erase` print the number of derived artifacts citing the claim and the
   `claim impact` command to list them. `erase` adds them to its "still holds copies" report (§7.7).

**Stays open:** automatic regeneration of affected descendants (the Z6 dependency DAG, canonical spec §Z6).

## 2. IOU-Z2-2: decision supersession links

**Today.** 878 decision pages; frontmatter `title, type, project, status, tags` (`scripts/memory.py:166-181`);
status is free text (live: accepted 839, proposed 32, superseded 6, decided 1); 0 pages carry a supersession link
in frontmatter. `decision_compare.py:82` already treats `superseded` as inactive. The legal frontmatter edit path
is `memory.set_decision_project` (`memory.py:202-244`). Graph edges: `mentions`, `derived_from`
(`graph_build.py:104-124`).

**Design.**
1. `zurvan decision supersede <old> --by <new> --reason "…"`: one operation. On `old`: `status: superseded`,
   `superseded_by: <new slug>`, and a dated line under `## Status` ("Superseded by [[new]]: reason"). On `new`:
   `supersedes: <old slug>`. All pages are validated before any byte lands. Refused (closed codes): unknown page
   (`DECISION_UNKNOWN`), `old == new` or a cycle (`DECISION_CYCLE`), `old` already superseded or `new` not current
   (`DECISION_NOT_CURRENT`), empty reason (`REASON_REQUIRED`).
2. `zurvan decision history <slug>` (read-only) walks `supersedes`/`superseded_by` both ways and prints the chain.
3. Graph: a `supersedes` edge (new → old) from the frontmatter scalar.
4. Digest and decision listings (`agent_workflow.py:157-163`, `project decisions-*`) skip a decision with
   `superseded_by:`. **Search is unchanged**: a superseded decision stays findable, its page says so. (Hiding
   decisions from the index would be a retrieval change and would make "what did we decide before" unanswerable.)
5. MCP: `zurvan_decision_supersede` (write, gated by read-only mode) in the Python server, the Rust bridge
   (`rust/zurvan-mcp/src/bridge.rs` tool map and write list), `scripts/mcp_parity.py`; the Rust binary is rebuilt
   and installed as in 2026-11-15c (previous binary kept as a `.bak` hard link).

**Stays open:** linking the 75 prose supersessions and the 6 unlinked `status: superseded` pages needs a human or
Z7 pass (no automatic linking: a wrong link hides a live decision from the digest). Contradiction detection is Z7.

## 3. IOU-Z2-1: subject / predicate / object

**Today.** `revisions.subject_id`, `predicate_id`, `object_json` exist, nullable, hashed, carried by `_carry`
(`claim_store.py:99-101`, `claim_ledger.py:193-198`); nothing writes them (0 live rows). No entity id scheme;
entity pages are keyed by `slug(name)` (`wiki_merge.py:163-174`). Extraction prompt has no S-P-O
(`scripts/prompts/extract_source.md:26-38`). No Z3 consumer contract exists yet.

**Design.**
1. A checked-in predicate vocabulary `scripts/claim_predicates.json` (small, closed, each with a one-line meaning;
   `related_to` as the explicit fallback) and a validator. Subject = an entity slug (`ent:<slug>`, the same slug
   the entity pages use). Object = JSON, exactly one of `{"entity": "ent:<slug>"}`, `{"value": "<text>",
   "unit": "<unit>"?}`, `{"date": "<ISO date>"}`.
2. `claim add`, `claim revise` and `claim supersede` take `--subject --predicate --object` (all three or none);
   `ClaimState`, `claim show` and `claim history` expose them; `revise` with only S-P-O is a legal metadata
   revision (reason required as always). MCP contracts unchanged.
3. Extraction: the prompt asks for an optional `spo` per claim; `plan_claim_records` validates it and drops an
   invalid triple (the claim is still written, a warning is logged). The mock provider emits a valid triple.
4. Backfill, reviewed and opt-in: `zurvan claim structure --propose [--limit N] --out proposals.jsonl` asks the
   configured provider for triples for current claims without one and writes ONLY the proposals file (refuses the
   mock provider); a human marks entries `"approved": true`; `zurvan claim structure --apply proposals.jsonl` writes
   one `revise` per approved entry (`method=model_extraction`, reason "S-P-O backfill (IOU-Z2-1)"), one operation.

**Not done here (Raouf's call):** running the backfill on the 555 live claims (model spend plus review). Splitting
sentence claims into atomic ones (a one-to-many supersede) is deferred to Z3, which owns the consumer contract.

## 4. IOU-Z2-4: PDF page locators

**Today.** Selectors are W3C `TextQuoteSelector` + `TextPositionSelector` + `state` (`claim_evidence.py:93-101`);
readers `utf8` and `extract_text@1` (`:24`); `ingest._extract_pdf` joins pages and normalises, losing page
boundaries (`ingest.py:82-105`). 0 live claims cite a PDF directly; images are `pending-visual` stubs that nothing
extracts (`ingest.py:346-370`, `extract.py:117-120`).

**Design.**
1. A reader `pdf_pages@1` (pypdf, the declared dependency): per-page text, never merged, never normalised (admission
   forbids normalisation, `evidence_admission.py:10`). `claim add/revise/supersede --source x.pdf` selects it
   automatically.
2. The selector keeps `TextQuoteSelector` and gains `refinedBy`-style `FragmentSelector {"conformsTo":
   "http://tools.ietf.org/rfc/rfc3778", "value": "page=N"}` (1-based page index). `locator_kind` stays
   `text_quote`, so no schema migration. A quote that occurs on more than one page is refused like any ambiguous
   quote unless prefix/suffix disambiguate it.
3. `verify` for this reader: file bytes unchanged → `intact`; the quote found on page N → `moved` (bytes changed,
   same page); found on another page → `moved` with detail `page N -> page M` (reported, like any move; the stored selector is
   not rewritten);
   otherwise `changed`. Existing outcome vocabulary only.
4. Tests build tiny PDFs offline (a fixture writer with pypdf or PyMuPDF), covering: a quote on page 2, a quote that
   moves to page 3, a quote on two pages, a changed page.

**IOU-Z2-4b, closed 2026-11-16 (Raouf: "proceed and fix and close all").** Image region locators: `zurvan claim
add|supersede --source img.png --region x,y,w,h` records a W3C `FragmentSelector` conforming to Media Fragments 1.0
(`xywh=pixel:x,y,w,h`), the file's sha256 and the sha256 of the region's decoded RGBA pixels (reader
`image_region@1`, Pillow; `locator_kind` `media_region`, so the claims schema moved to v2: the CHECK widened, a v1
store migrates on its first read-write open with every evidence row and the hash chain unchanged). No quote, no
capsule: a human states what the region shows. `verify`: same file → `intact`; file changed, region pixels unchanged
→ `moved`; region pixels changed, region outside the image, or undecodable → `changed`; missing → `gone`. Extraction
still never reads images (that is a model phase's job); video and audio regions (`t=`) are not built.

**Deferred minors of the final review, all closed 2026-11-16:** extraction from a PDF records `pdf_pages@1` when every
quote occurs once in the per-page text; whitespace-normalised verify is per page; `claim impact` skips evidence from
another registered project; the old decision's `## Status` says `superseded` and carries the note; `decision history`
lists every predecessor of a merge; a relative decision path is store-relative; `claim structure --propose` scans
each claim with Boundary as the PUBLIC_ARTIFACT sink before sending it (a remote provider is off the machine).
