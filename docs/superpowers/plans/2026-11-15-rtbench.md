# RTBench (IOU-Z2-5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A system-neutral record-time benchmark: one deterministic generator, a reference oracle independent of Zurvan, a structured track (S) and a natural-language track (N), baselines, a Zurvan adapter, a scorer, a CLI and recorded dev-split runs.

**Architecture:** A new package `scripts/rtbench/` holds pure-stdlib modules (generator, oracle, renderer/parser, scorer, baselines, runner) plus one Zurvan adapter that drives `scripts/claim_ledger.py` in a temporary store per case. Gold answers come only from `oracle.py`. The CLI joins `scripts/cli.py` as `zurvan bench rtbench …`.

**Tech Stack:** Python 3 standard library (`random`, `json`, `hashlib`, `secrets`, `re`, `math`, `dataclasses`), pytest; Zurvan's claim ledger for the Zurvan adapter only.

**Spec:** `docs/superpowers/specs/2026-11-15-z2-record-time-benchmark-design.md`

## Global Constraints

- Generator, oracle, renderer, parser, scorer, baselines and runner import only the standard library and `scripts.rtbench.*` (spec §3). `oracle.py` imports nothing from `scripts.claim_*` or `scripts.knowledge_*` (spec §2 anti-goal, R2).
- Same generator version + seed → byte-identical files: canonical JSON (`sort_keys=True`, `separators=(",", ":")`, `ensure_ascii=False`), one object per line, `\n` endings (spec §3, R1).
- `GENERATOR_VERSION = "rtbench-1"`. Any change to generated bytes bumps it and re-registers the dev digest.
- Splits: `dev` = 200 cases from `DEV_SEEDS = list(range(1000, 1200))`; `holdout` = 200 cases from seeds in `~/.zurvan/instruments/rtbench_holdout.seeds` (mode 0600), created with `secrets.randbits(63)` on first generation (spec §7, §11).
- Holdout files and seeds never in git; registered in `eval/datasets.json` by whole-file digest only; a holdout run reports aggregates, never items (spec §2, §7, §9, R9).
- Case sizes: 8–60 events, 2–8 slots, 10–30 questions; about 20% of cases with an erase, about 30% with an abort, about 30% with valid-time intervals (spec §7).
- Headline = macro accuracy over Q1–Q5; Q6 is a control reported separately (spec §6.3).
- Validity bar: oracle 100% on both tracks; overwrite and append-only baselines each ≤ 0.60 headline on both tracks of dev. Fix sampling, never the threshold (spec §6.5).
- Question sampling: at least half of Q1–Q4 at a tick immediately before or after a change to the asked slot; final-tick questions ≤ 20% of Q1–Q4; Q5 `yes` and `no` each ≥ 40% across a split (spec §6.1, §6.5).
- Tests never write the live store: the Zurvan adapter uses a temporary `ZURVAN_ROOT` per case (spec §2, R8).
- Reports go to `~/.zurvan/reports/rtbench-<adapter>-<track>-<split>-<date>.{json,md}` by default (spec §9).
- Change protocol: dated `Raouf:` entry in AGENTS.md and CHANGELOG.md; AGENTS.md keeps two entries; `public_repo_guard.py`, `git diff --check`, full suite green before the last commit.

## Review Focus

- A case where the same slot is superseded twice and then retracted: Q3 at each tick must step value → value → value → `none`; tested in Task 2 (`test_hand_case_supersede_chain`).
- A question at tick 1 (before most changes) and at the final tick: off-by-one in "tick ≤ t" folds; tested in Task 2 (`test_boundary_ticks`).
- Track N parse of a value containing a comma thousands separator (`4,210 tonnes`): normalisation must equal `4210 tonnes`; tested in Task 4 (`test_values_with_separators_round_trip`).
- An abort inside the Zurvan adapter that leaves the store SUSPECT: the adapter must reconcile and keep going, never write the live store; tested in Task 7 (`test_abort_reconciles_in_temp_root`).
- A holdout run must not print or store per-item rows; tested in Task 8 (`test_holdout_report_has_no_items`).

import random
from scripts.rtbench import GENERATOR_VERSION
from scripts.rtbench.canon import dumps
from scripts.rtbench.vocab import make_slots
from scripts.rtbench.events import generate_events

def _gen(seed):
    rng = random.Random(seed)
    slots = make_slots(rng, rng.randint(2, 8))
    return slots, generate_events(rng, slots, "2026-01-05")

def test_version_is_pinned():
    assert GENERATOR_VERSION == "rtbench-1"

def test_same_seed_same_bytes():
    assert dumps(_gen(7)) == dumps(_gen(7))
    assert dumps(_gen(7)) != dumps(_gen(8))

def test_invariants_hold_over_many_seeds():
    for seed in range(300):
        slots, events = _gen(seed)
        assert 8 <= len(events) <= 60
        ticks = [e["t"] for e in events if e["type"] != "abort"]
        assert ticks == list(range(1, len(ticks) + 1))
        believed, dead, by_slot = set(), set(), {}
        for e in events:
            if e["type"] == "abort":
                assert e["t"] is None and e["inner"]["type"] != "abort"
                continue
            if e["type"] == "assert":
                assert by_slot.get(e["slot"]) is None          # one believed statement per slot
                believed.add(e["sid"]); by_slot[e["slot"]] = e["sid"]
            elif e["type"] == "supersede":
                assert e["old"] in believed and by_slot[e["slot"]] == e["old"]
                believed.discard(e["old"]); dead.add(e["old"])
                believed.add(e["sid"]); by_slot[e["slot"]] = e["sid"]
            elif e["type"] in ("retract", "erase"):
                assert e["sid"] in believed                  # never targets a dead statement
                believed.discard(e["sid"]); dead.add(e["sid"])
                by_slot = {k: v for k, v in by_slot.items() if v != e["sid"]}
            elif e["type"] == "revise":
                assert e["sid"] in believed
        values = [e.get("value") or e.get("inner", {}).get("value") for e in events]
        values = [v for v in values if v]
        assert len(values) == len(set(values))              # values unique within a case

def test_mix_matches_the_spec_over_dev_sized_sample():
    n = 200
    gens = [_gen(1000 + i)[1] for i in range(n)]
    erase = sum(any(e["type"] == "erase" for e in ev) for ev in gens) / n
    abort = sum(any(e["type"] == "abort" for e in ev) for ev in gens) / n
    valid = sum(any(e.get("valid_from") or e.get("valid_until") for e in ev) for ev in gens) / n
    assert 0.12 <= erase <= 0.30 and 0.20 <= abort <= 0.40 and 0.20 <= valid <= 0.40

- [ ] **Step 3: Implement `fold(events) -> Timeline` and `answer(tl, question) -> object`**

`fold` walks events, skipping `abort`, recording `born`, `ended`/`end_kind` and `erased` (an erase sets `ended`, `end_kind="erased"`, `erased=True`). "Believed at t" = `born <= t` and (`ended is None` or `ended > t`). Q2 at t: `not_yet` if `born > t`; else `end_kind` if `ended <= t`; else `believed`. Q5: `"yes"` if any non-erased statement of the slot with that value was ever born. Q6 = Q3 at `final_tick`. Q1 sorts sids (or values, mapping erased statements to `"[erased]"`).

    for i, s in enumerate(DEV_SEEDS):
        case, _ = generate_case(s, "x")
        changes = {}
        for e in case["events"]:
            if e["t"] is None: continue

```python
def wilson(k, n) -> tuple:
    if n == 0:
        return (0.0, 1.0)
    z, p = 1.96, k / n
    d = 1 + z * z / n
    c = (p + z * z / (2 * n)) / d
    h = z * ((p * (1 - p) / n + z * z / (4 * n * n)) ** 0.5) / d
    return (c - h, c + h)
```
